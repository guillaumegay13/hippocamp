# Current state

Relay verifies signed webhooks with shared HMAC-SHA256 logic and queues production deliveries in Postgres via pg Pool (DATABASE_URL or standard PG* variables). Redis removed at user request because ops will not run it. Apply migrations/001_deliveries.sql before startup. The deliveries table holds body, metadata, attempts, status and available_at lease; acceptance returns 202 pending after persistence. Atomic FOR UPDATE SKIP LOCKED claims allow concurrent workers; leases last 60 seconds, outbound timeout is 30 seconds. Five total attempts, retry only 5xx, local Promise/setTimeout backoff 100/200/400/800 ms based on persisted counts. Attempts recorded before sending; interruption may duplicate a request or consume an attempt. Recipients deduplicate by stable delivery ID.

GET /admin/deliveries and /admin/deliveries/:id expose only id/source/target/receivedAt (Unix ms)/status/attempts; never payloads or extra stored fields due to PII contract. Unknown IDs return 404; errors generic 503. Deployment supplies admin access controls. src/app.ts exports createApp; src/server.ts owns pg Pool and worker lifecycle.

QueueStore decouples workers from storage. Tests use fake queue/database and MemoryStore; no external service or optional integration test. npm test passes 18 tests. SQL has not been exercised on live Postgres. Build clears dist before compilation to prevent stale tests. MemoryStore and inline delivery remain available.
