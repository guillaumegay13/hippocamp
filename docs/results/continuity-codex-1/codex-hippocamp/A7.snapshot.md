# Current state

Relay verifies signed webhooks with HMAC-SHA256 and queues production deliveries in Postgres via pg Pool (DATABASE_URL or standard PG* variables). Redis removed because ops will not run it. Apply migrations/001_deliveries.sql and 002_attempt_history.sql before startup. Acceptance returns 202 pending after persistence. Atomic FOR UPDATE SKIP LOCKED claims support concurrent workers with 60-second recovery leases and 30-second outbound timeouts.

Five total attempts; retry only 5xx. SOURCES[source].retryDelaysMs optionally configures four integer millisecond delays (0–2147483647), default 100/200/400/800; invalid schedules fail app startup. Worker schedules retries via available_at, without sleeping under a lease. Uses current source configuration for each next retry, including existing deliveries; already scheduled times remain. Inline delivery uses timers. No new migration for retry settings. Attempts recorded before sending; interruption can duplicate a request or consume an attempt. Recipients deduplicate by stable delivery ID.

GET /admin/deliveries and /admin/deliveries/:id expose only id/source/target/receivedAt (Unix ms)/status/attempts. GET /admin/deliveries/:id/attempts exposes safe timing/status/outcome history, persisted as attempt_history JSONB. Legacy history may be absent. Never expose payloads or raw errors. Unknown IDs return 404, storage errors generic 503. Deployment supplies admin access controls.

src/app.ts exports createApp; src/server.ts owns pg Pool and worker lifecycle. QueueStore decouples storage. Tests use fake queue/database and MemoryStore; npm test passes 21 without external services. SQL has not been exercised against live Postgres. Build clears dist before compilation. MemoryStore and inline delivery remain available.
