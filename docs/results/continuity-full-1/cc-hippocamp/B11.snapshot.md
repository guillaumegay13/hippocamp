## 2026-11-04T09:05:32.098Z — Parallel chunk posting with multiprocessing (uncommitted)

Agent: claude
Session: mcp-6c9c2071

Keywords:
- [[multiprocessing]]
- [[parallel]]
- [[chunks]]
- [[load-file]]
- [[workers]]

User asked for parallel import, one process per chunk. load_file got workers=1 default (sequential, keeps in-process FakeClient tests working); CLI passes os.cpu_count(). ProcessPoolExecutor(max_tasks_per_child=1) gives a new process per chunk, with at most `workers` running at once. In-flight submissions are capped at 2*workers so the file still streams. Dedupe stays in the parent so it covers the whole file. Tradeoffs to remember: chunk post order is no longer deterministic; when a post fails, chunks that already posted stay posted; the client must be picklable. Work is HTTP-bound, so threads would also have done the job. Not committed yet.
