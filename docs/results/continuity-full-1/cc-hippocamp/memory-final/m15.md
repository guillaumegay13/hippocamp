## Open
- Store is still MemoryStore, so delivery records and attempt history don't survive a restart; only pending retries in the Postgres `deliveries` table do. A PostgresStore on that table, plus a delivery_attempts table, is the natural step. It must implement `Store.listPage` as `WHERE (received_at, id) < ($1,$2) ORDER BY received_at DESC, id DESC LIMIT n` and needs an index on (received_at DESC, id DESC). (The admin list being in-memory could also be the "slow lookup".)
- Admin API filtering doesn't exist yet. Unconfirmed whether target URLs count as sensitive.
- Unconfirmed whether network errors should retry (currently 5xx only).
- fetch has no timeout. A hung send that outlasts the 30s lease could cause a duplicate attempt.
- Attempt-history field names, storing fetch error.message, and returning an empty list for deliveries with no attempts were my choices; the user hasn't confirmed them.
