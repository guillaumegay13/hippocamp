On 2026-11-04 ops ran a backfill that moved old retries (from the Redis era) into the prod Postgres `deliveries` retry table.

**Why:** the prod table now holds migrated rows as well as new ones, not just rows written by the current code.
**How to apply:** before changing the `deliveries` schema or the job JSON format, assume prod has existing backfilled rows that must stay readable. Ask about migrations instead of assuming an empty table. Related: [[relay-constraints]].
